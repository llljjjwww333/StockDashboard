检查日期：2026-11-01（周日，非交易时段）。检查对象为本地工作区 `E:\Stock Dashboard`。原有未提交的界面改造继续保留；改造前 18 个主要文件保存在根目录 `.baseline-before-source-upgrade.zip`，未提交、未推送、未发布。

## 现在如何打开

- 看板：http://127.0.0.1:5173
- API 文档：http://127.0.0.1:8000/docs
- 重启后双击根目录 `启动看板.cmd`。它会检查现有服务并复用，后台启动缺失的服务；日志在 `.local/`。
- 当前验证的是本地网页。仓库只有 Render 部署模板，没有可确认归属的生产域名，因此没有把同名 Render 站点当作本项目线上站点。

## 已确认的问题与修复

| 原问题 | 本轮处理 |
| --- | --- |
| 前端默认 8001、后端部署 8000 | 默认同源，Vite / Nginx 代理到后端，HTTP 与 WS 共用地址推导 |
| 数据源失败时生成随机 K 线，并可能继续组成报价 | 删除模拟曲线和默认价格；无真实数据返回 503，真实旧缓存携带 stale 标记 |
| 页面固定显示“数据连接正常” | 根据 WebSocket 连接状态展示连接、重连；行情错误单独提示 |
| REST 与 WS 各创建数据服务，逐只拉取 | 单进程共享服务、2 秒报价缓存、合并订阅和中美股批量报价 |
| 原报价循环固定 10 秒，缓存 12 秒 | 工作日常规交易时段目标 2 秒；休市 30 秒，支持配置 1–30 秒 |
| 北交所 920 开头的股票被发送到上交所 | 修正为 bj 前缀，验证 5,577 只股票完整取回 |
| 全市场采集阻塞首屏；美股榜单同步网络调用阻塞异步服务 | 缓存优先、后台更新完整快照；榜单在线程中并行读取 |
| 财联社旧接口 404，新闻长时间等待后返回空列表 | 改为新浪 / 东方财富并行读取，约束等待时间，失败返回明确状态 |
| 旧 Docker 使用 Node 18 / Python 3.10 | 改为 Node 24 / Python 3.11；Nginx 统一 HTTP/WS 入口，替换缺失 curl 的健康检查 |
| 前端 lint 16 处错误、切换图表后悬停索引可能越界 | 修复 ref 传递及悬停索引，构建与 lint 均通过 |

Node 版本变更依据：[Vite 官方环境要求](https://vite.dev/guide/)。本项目直接使用 `datetime.UTC`，需要 Python 3.11 或更高版本。

腾讯美股 K 线响应的报价类型明确出现 `delay`。**两秒是检查源站的目标间隔，不是交易所到浏览器的延迟保证，也不是逐笔成交推送。** 页面已展示美股延时报价与源站时间。Yahoo 的行情也须按市场区分延迟，参见其[官方数据覆盖和延迟说明](https://help.yahoo.com/kb/SLN2310.html)。

## 实测与验证证据

- `baseline-sources.json`：改造前请求记录。A 股热点约 53.5 秒后回退到样本；新闻约 13.5 秒后返回 0 条；美股单只报价约 6.0 秒。
- `upgraded-sources.json`：中途检查保留的失败记录，包括 Yahoo TLS 失败和历史行情 503；`sources-before-news-fix.json` 保留东方财富新闻缺参数的失败；没有删除不通过的结果。
- `final-sources.json`：本轮最终 21 个来源 / API 检查全部成功。腾讯三只美股批量请求约 0.44 秒；新闻返回 20 条约 1.03 秒。行情或热点缓存命中所需的几毫秒不代表上游速度。
- `market-refresh.json`：后台更新后的市场状态。A 股为 full_market、5,577 只；美股为样本概览。缓存请求可先返回 stale 数据，再由后台刷新。
- `browser-check.json` 与 `overview.png`、`markets.png`、`news.png`、`outage.png`：真实 Edge 浏览器检查。首个报价约 0.48 秒出现；五个默认标的均收到推送；页面无 JavaScript 异常、正常流程无 API 错误；人为阻断报价和历史源时显示错误与 `--`。
- `stream-check.json`：两个独立 WS 客户端连续观察 36 秒，均收到两批相同源快照，源抓取时间间隔约 30 秒，符合周日调度。
- 后端 12 项回归测试通过，覆盖不伪造数据、缓存失效、15 个并发读请求共享一次抓取、部分股票缺失、时区与单位、北交所路由及退订清理。
- `npm run build`、`npm run lint`、`git diff --check`、`docker compose config --quiet` 通过。

这些是本机网络条件下的单次检查，前后请求的缓存与并发状态不同，不能当作严格的性能基准或长期可用率。
